# Project notes for the agent

- AGENTS.md lists the idiosyncrasies of the data and the logic the first build turned up (the spine and its sources by era, the coach of record, ESPN's holes, positions, censoring, the columnar format). Read it before changing a ledger builder or the engine, and add to it when a gate or a reader teaches us a new one.

- What it is: a query engine for college football comparisons at the same point ("Kirby Smart has 85 wins through his first 100 games"). A reader sets a five-slot sentence (who · did what · how much · over which games · against whom) and the board ranks every career, every tenure at one school, or every season of the kind by its value at that window; a row opens inline under itself and reads against a peer; a coach's, a team's or a player's page lists every comparison it leads. It is the NBA Comparator (`~/Projects/nba-comparator`, the newest sibling: named boards, llms.txt, IndexNow, entity pages, the columnar ledger) over three ledgers instead of one, with a `kind` slot in the query. The planning spec is `specs/cfb-comparator.spec.md`; the research that chose the sources is under `research/`. Keep the comparator engines (NFL, WNBA, NBA, this) in step when one learns something.
- Data: three ledgers, built by `scripts/build-ledgers.mjs` (`npm run ledger`) from `data/raw/` (gitignored; `npm run fetch`) and the committed history. The game spine: `data/history/games-1869-1935.json.gz` (James Howell's pages parsed once by `scripts/build-history.mjs` from Streak King's cached copy of jhowell.net) and College Football Streak King's committed payload from 1936 (`data/raw/streak-king-payload.json`, fetched from that repo's main: Howell's and Repole's scores with its errata, the AP rank of both teams at kickoff, neutral/conference/postseason flags, and the head coach of every team-game from CFBD's rows resolved game by game plus its researched overrides). The coach of record before 1936 is `data/ref/coaches-1869-1935.json` (`scripts/build-coaches-pre1936.mjs` from Wikipedia's coach navboxes, one coach per team-season, CC BY-SA 4.0). Players: ESPN's box scores (`player_box_<season>.csv`, plus the rows only the older `.csv.gz` has), schedules and rosters from the sportsdataverse releases, 2004 on, joined to the spine by ESPN team id and date for the ranks. `scripts/lib/window.mjs` holds the first seasons (1869, the AP poll's 1936, the box scores' 2004) and the running season, and is the only place a year is typed.
- The ledgers are columnar (`src/lib/ledger.ts` decodes them): `src/data/<kind>.json` is the entities (id, name, debut, `censored`, a player's position and its source) each with its slice `[lo, hi)` of the game arrays, and `src/data/cols/<kind>/<name>.bin.gz` one gzipped typed array per column over every game (the day since 1869-01-01, the season, the flags, the team, the opponent, the team's game number, both scores, both AP ranks; the player ledger adds 31 stat columns, yards as signed 16-bit, sacks in halves). A game is an index; `gameAt` builds an object only for display. The page fetches a kind's entity file and base columns as assets (`src/ledger-client.js`, nothing bundled: the player file is 6 MB) and the stat columns a query reads as it needs them (`src/lib/load.ts`). Coach and team ledgers have no stat columns: their stats read the game itself (`stats.ts`: wins, points, margin, vs ranked, vs top 10, road, conference, bowls, shutouts, routs, one-score wins).
- Rulings the words rest on (also in `Notes.jsx`): a game is one the entity took part in (a player's game is a box-score line; there is no starter flag in football, so a quarterback's wins are his team's results in the games he has a line in); a win is the result of a game in the sequence, a tie neither; "first N games at one school" is a tenure (`seq: tenure`, one row per contiguous stint); "team games of a season" count the team's schedule on the spine, so a game ESPN never had is a gap the window still counts; a season that is over fills a longer window whole, and so does a career or a stint that is over (`isActive`); bowls and the playoff are in by default (`scope: all`) and `scope=reg` takes them out; conference title games are regular season; ranked and top-10 read the AP poll in effect at kickoff from 1936 (`RANK_UNKNOWN` before, and before a season's first poll until 1950, which sits the entity out of those fields for that window); a clean line ("no interceptions thrown") needs ten attempts or five touches (`played`, inside `holds()`); a coach's and a program's games count only in seasons Howell lists the school as major (`F_MAJOROPP` says whether the opponent was); every result is on-field (vacated wins stand, forfeits as played); ranks are competition ranks with ties.
- The known-answer gate is `src/lib/query.test.ts` (and `npm run gate` prints the same numbers with the publisher's): Rockne 105-12, Bryant 323, Paterno 409 and his 200th in game 246, Osborne 255-49, Meyer 187 and 24-0 at Ohio State, Saban 297 on the field (292 official), Smart 85 through 100 games and his 100th in game 117, Petersen 117 (the NCAA says 118), Woodruff 111 (the NCAA says 109), Wilkinson's 47, Oklahoma's 47, Georgia's 29, Northwestern's 34, LSU's 726, Burrow's 5,671/60/65/6,039, Zappe's 5,967/62, Keenum's 19,217/155, Gabriel's 18,722/155, Jeanty's 2,601 and 14 100-yard games, Gordon's 2,587 and 408, Perine's 427, Chase's 1,780, Smith's 1,856, Holliman's 14, plus the holes pinned as holes (Brennan 42 for Hawai'i 2006, Harrell 464 and Crabtree 119 for the UTEP game). Add a gate for every factoid the site is asked to reproduce, with the publisher named and the difference noted where there is one; the receipts live under `research/factoids-*/`.
- Code layout: `src/lib` is TypeScript (`npm run typecheck` checks it and the worker), components JSX. `ledger.ts` the format and decoder (`Kind`, `Entity`, `stints`); `load.ts` the column fetching; `query.ts` the engine (`evaluate` → ranked rows, the ones still inside the window, the censored/early/partial counts; `curve`, `crossings`, `toMatch`; `queryCols`; `querySince` reads the ledger's `statSince`); `stats.ts` the catalog (each stat names its kinds, its columns, its first season per kind, its thresholds, `bad` for the futility direction, `tick` for milestones); `words.ts` every sentence (kind-aware: `whoWords`, `unitWords`, `his`); `compare.ts` the panel's comparison; `share.ts` the words a link carries; `url.ts` the query in the URL (one param a slot, `kind` the ledger, `t` the open row, `vs` its peer); `landing.ts` the named boards; `records.ts` the mine (`shapesFor(kind)`); `analytics.ts` the `track` helper. `pos` is a filter on the player field only.
- The page, top to bottom: the dateline with the finder (per kind), Ko-fi and share; the h1; the sentence (the first word picks the kind, or a position group under "players"; a kind switch starts from that kind's default board, `DEFAULT_BY_KIND`); the footnote; the board with the open row's panel inline under it; More boards by kind; What to read next; the citing ask and Ko-fi; Method (`id="method"`, folded sections); the footer; comments. A kind's ledger loads when the reader switches to it, the last board staying on screen meanwhile. `document.title` is set client-side with the words the worker writes.
- Named boards (`src/lib/landing.ts`): 42 curated queries across the three kinds, each at its own path (`/fastest-to-100-wins-as-a-head-coach/`), prerendered with the searcher's phrase as the h1, the leader in a lead line, an ItemList of the top ten and the worker's card; the path is the query's canonical address (`hrefOf`). Entity pages: `/coach/<id>/`, `/team/<id>/`, `/player/<id>/` (`App.jsx` `parseRoute`, `EntityPage.jsx`); `npm run records` (`scripts/build-records.mjs`) mines what every entity leads and writes `public/entities/<kind>/<id>.json` plus `index.json` per kind (the finder's list); the prerender writes each page with its file embedded (`#entity-data`), its own card (`scripts/lib/og-entity.mjs`), the sitemap and `llms.txt`; `scripts/indexnow.mjs` pings IndexNow after a deploy.
- Group pages (`src/lib/groups.ts`, `GroupPage.jsx`): the best players of each position at each school (`/school/<spine id>/<position slug>/`, e.g. `/school/alabama/wide-receivers/`) and in each FBS conference (`/conference/sec/quarterbacks/`), every player with five or more games there ranked by the position's first metric (`GROUP_METRICS`), the top eight drawn as cumulative lines per metric, the table of all of them; the prerender computes each page's data and embeds it (`#entity-data`), draws its card (`scripts/lib/og-group.mjs`) and writes the two index pages (`/school/`, `/conference/`) that link every one. 1,008 pages at the first build. The player panel, the player and team pages and More boards link into them.
- Vite + React static site for GitHub Pages under drewhoover.com, from the dataviz-project-template: `package.json` "name" is the URL slug and must equal the repo name; `site.config.js` the title and OG copy; `npm run build` is the records mine, `vite build` and `scripts/prerender.mjs`, so `main.jsx` hydrates and nothing reads `window` during render. The repo is `DrewHoo/cfb-comparator`, live at `https://drewhoover.com/cfb-comparator/`; `.github/workflows/deploy.yml` deploys on every push to `main` (the Pages build, then IndexNow, then the worker job) and refetches on Sunday and Tuesday at noon UTC in season, caching `data/raw` across runs.
- Social previews: the share worker (`workers/share/`, name `cfb-comparator-share`) sits on `drewhoover.com/cfb-comparator/*`. For a board address whose query says more than the root it rewrites `<head>` with the words from `src/lib/share.ts` (a crawler's request also loads the query's ledger and names the leader, or the open row read against its peer) and points `og:image` at `/cfb-comparator/share/og.png?<the same params>`, drawn with workers-og (`card.ts`) from the ledgers the prerender publishes under `dist/data/` (raw-GitHub fallback): the board's top rows, or with a row open (`?t=`) the comparison card, both sides against the `vs=` peer (else the leader) with the panel's lines and curves, the NFL Comparator's card; every glyph stays inside the centered `SAFE = 720` column; entity pages pass through with their own static cards. `CARD_VERSION` in `index.ts` keys the edge cache: bump it with any change to what a card draws. Local: `npm run build`, `npx vite preview --port 4175`, `npm run worker:dev`, then `http://localhost:8789/cfb-comparator/share/og.png?n=100`. The worker holds a kind's ledger for the UTC day (the player ledger about 10 MB resident plus a column per stat asked for).
- Dev server: `npm run dev` (the launch config runs it on 5178; the NBA site is 5177, the WNBA 5176, the NFL 5175). Tests: `npm test` (Vitest; `rtk proxy npx vitest run --reporter=verbose` to read the output). Images: `npm run gen:favicon` copies drewhoover.com's own favicon set; `npm run gen:og` draws `public/og.png` and `public/card.png` from the real default board with Georgia Bold from the Mac. Both are committed; re-run `gen:og` after a redesign or when a fresher board is worth committing, and open the PNGs.
- Ko-fi is `KOFI_URL` in `Notes.jsx`, three placements, each `track('kofi', { from })`: the icon bar, the notes line, the footer (`Footer` in `Notes.jsx`, on the board, the entity pages and the group pages). Look: College Football Streak King's (the dark stadium palette, Georgia Bold h1 and h2, Graduate for numbers, Source Serif for words, Plex Mono labels, dashed-underline pickers). Every select is `Picker.jsx`; no native `<select>`. Rust is for data, never chrome.
